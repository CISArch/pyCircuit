# 权重划分 vs 未划分：多线程仿真 cycles/s 提升对比（DavinciBaseLine 与 BoomCore）

日期: 2026-11-19 ｜ 机器: 32 逻辑核
详细方法与完整数据: [RocketCore/p2w_trace_sched.md](RocketCore/p2w_trace_sched.md)、[BoomCore/report.md](BoomCore/report.md) §3b

## 0. 摘要

- 权重划分（LPT+相关性装箱）相对未划分（naive 动态队列）的提升**只出现在低并行度非饱和区**，幅度由任务成本不均匀度决定: DavinciBaseLine 34-trace（成本跨度 2400x）4 线程 **+8~10%**；BoomCore 100 任务（跨度 1.4x）4 线程 **+5%**
- **≥8 线程提升归零**（提升 ≤2.7%）: 未划分的 naive 自己已贴近地板（straggler 或带宽墙），无调度空间可吃
- **带宽饱和区（16+ 线程）静态箱反而劣化 −12~−15%**: 动态队列能对进程速度随机波动做机会性再平衡，静态箱把结构性失衡锁死
- 划分**不抬高吞吐天花板**（DavinciBaseLine 峰值 72k→72.5k，+0.9%），只加快贴顶；**抬高天花板靠任务切分**（+162%，72.5k→190k）

| 8 | 8.13s / 71.0k | 8.16s / 70.8k | ≈0 | ~8.5s / ~68k | 无收益（撞带宽） |

| 16 | **7.96s / 72.5k** | 9.45s / 61.0k（高方差） | **−15%（劣化）** | 5.31~5.54s / 105~109k | +47% |

- naive 峰值 ~72k c/s（7thr），wpt 峰值 72.5k（12thr）: **划分只 +0.9%**

## 3. 跨架构共性规律

1. **收益 ∝ 任务成本不均匀度**: 34-trace 套件单条 straggler 占总功 16%、跨度 2400x → +8~10%；BOOM 跨度 1.4x → +5%。成本越均匀，naive 队列自平均越强，划分越无用
2. **收益只在非饱和区**: 饱和前每核吞吐未降时，尾部对齐才有意义；进入带宽墙后墙钟由硬件决定
3. **饱和区静态箱有害**（BOOM 16thr −12%、DavinciBaseLine 16thr −15%）: 饱和态进程速度随机波动，动态队列自适应，静态箱锁死失衡且大任务不可分（BOOM `mini_nop`×10 使 16 箱预测极差 13.5% vs 4 箱 0.8%）
4. **划分与切分正交**: 划分解决「谁先跑、跑多久」（保序贴地板），切分解决「任务太大」（抬地板）。天花板数量级提升只能靠切分

## 4. 策略推荐

| 场景 | 推荐策略 | 预期收益 |
|---|---|---|
| 任务成本不均 + 并行度 ≤ 饱和拐点 | wpt 静态划分（剖面 10 条小任务拟合 `ms=a+b·hints`，成本 <2% 负载，模型可缓存跨日复用） | +2~10% |
| 高并行未饱和（如 34-trace 的 8~12thr） | wpt 或 naive 均可 | ≤3% |
| 带宽饱和区（每核吞吐显著下降） | naive 动态队列 | 静态箱反而 −12~−15% |
| 需要抬高吞吐天花板 | 模型引导自适应切分（份数由权重模型先验给出，hints 按行切，每片仍是合法回放流） | +37%~+162% |
