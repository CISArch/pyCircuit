# 稀疏注意力负载下的并行收益归因：为什么权重划分效果有限，而 1→8 线程仍有明显提升

日期: 2026-11-19 ｜ 套件: DavinciBaseLine 34-trace 回放（RocketCore）
关联: [p2w_vs_naive_mt_comparison.md](p2w_vs_naive_mt_comparison.md) ｜ [RocketCore/p2w_trace_sched.md](RocketCore/p2w_trace_sched.md) ｜ [RocketCore/per_trace_mt_scan.md](RocketCore/per_trace_mt_scan.md) ｜ [BoomCore/report.md](BoomCore/report.md)

## 0. 摘要

针对两个表面矛盾的问题给出数据归因：

1. **既然是稀疏注意力负载（负载天然不均），为什么 PPSIM 式权重划分没有明显效果？**
   ——因为稀疏注意力在这里造成的是「少数单体巨任务」，不是「细粒度任务混合不均」。权重划分只能治**分配不均**，治不了**任务不可分**。
2. **那为什么 1→8 线程并行仍有明显提升？**
   ——那部分提升来自**并行本身**（砍总功 Σ/N），任何调度（含 naive）都拿得到；与权重划分是两种正交收益。

总账：三种收益叠乘，11.4k → 190k c/s——**并行（1→8thr, 6.2x）× 划分（2/4thr, +2~10%）× 切分（12→32thr, +162%）**。

## 1. 概念错位：稀疏注意力 ≠ 调度意义上的负载不均

稀疏度决定每条 trace 的 **DUT 侧内容**（滑窗/分块模式 → PE 命令序列长短），但调度器看到的是**宿主侧每条 trace 的仿真耗时**。两者之间是高度线性的映射：

```
ms = 22.8 + 0.3734 × hints        （跨 34 条 trace，误差 <2%，大 trace 0.9%）
```

任务成本在派发前即可完美预测、执行中恒定——**不存在运行时才暴露的「负载波动」可供权重划分去捕获**。稀疏注意力改变的是「DUT 跑多少 cycles」，不改变「宿主每秒仿真多少 cycles」。

## 2. 真正的结构：三条「比箱子还大」的任务

34-trace 成本分布跨度 2400x，最重的三条恰好都是稀疏注意力变体：

```
csa 8.08s ｜ hca 7.55s ｜ swa 7.24s ｜ 其余 31 条合计 ~27s
```

任何划分器（含完美 oracle）的墙钟下界：

\[
\text{wall} \ge \max\Big(\Sigma/N,\ L_{max}\Big) = \max\big(50.63/N,\ 8.08\big)
\]

12 线程时 Σ/N = 4.2s，而 csa 单条 8.08s——**8 个核从第 4 秒起就在等 csa 结束**。这不是「谁分多了」，是装箱地板：**权重再准，也改变不了任务比箱大**。

反证即切分实验：把三条巨 trace 按 hints 行切开后，同一个 naive 动态队列直接 72k → 190k c/s（+162%）。瓶颈从来不是「不知道权重」（模型 1% 误差早就点名了该切谁），而是「物理上不可分」。

## 3. P2SIM 原生场景 vs 本场景：方法何时有效

| | P2SIM 原场景（repcut2） | 本场景（34 独立任务 + 动态队列） |
|---|---|---|
| 并行形态 | 把**一次**长仿真切给多进程**持续**跑 | 34 个独立任务 + 在线动态队列 |
| 划分质量的影响 | 直接决定稳态并行效率，无兜底 | 动态队列本身接近 LPT 最优 |
| 权重不均的后果 | 某些核**永久**过载 | 只影响尾部对齐（秒级） |
| IOU 相关性收益 | 避免跨分区通信（共享扇入） | 进程间只共享 LLC/页缓存 → 实测 ≤2.7% |

对「可预测成本的任务」，动态队列几乎最优，静态加权只剩尾部边际空间——所以 wpt 在 4 线程实拿 +9.6%（已达 oracle 界的 99.6%）。**不是方法失效，是天花板本身就那么高**。旁证：同一方法在 BOOM 套件（100 任务、成本跨度仅 1.4x）4 线程也拿到 +5%——可调度空间存在时它有效。

## 4. 1→8 线程的「明显提升」归因：并行本身，而非划分

| 线程 | naive wall | 每加一档省下的墙钟 | 生效约束 |
|--:|--:|--:|---|
| 1 | 50.63s | — | 总功 Σ |
| 2 | 26.16s | **24.5s** | 总功 Σ/N = 25.3s |
| 4 | 13.92s | **12.2s** | 总功 Σ/N = 12.7s |
| 8 | 8.13s | 5.8s（理想应到 6.33s） | **开始撞 straggler 8.08s** |
| 12 | 8.09s | ≈0 | straggler 地板 |
| 16 | 7.96s | ≈0 | straggler 地板 |
| 24 | 11.4s | 负（过订阅） | 带宽墙 |

拐点位置由算术决定：\(N^* = \Sigma/L_{max} = 50.63/8.08 \approx 6.3\)。

- **8 线程以内明显提升**：因为 N < 6.3 时 Σ/N 仍大于 8.08s，加线程是在砍「总功」侧的墙钟——这部分收益**与调度无关**，naive 就有
- 4→8 只提速 1.71x（不足线性 2x）：丢失的 0.29x 正是地板开始咬合的证据
- **「划分无空间」指的是另一件事**：给定 N，墙钟能否贴住 max(Σ/N, L_max)。8~16 线程 naive 自己（8.13/7.96s）就已贴住 8.08s 地板 → 空间为零，不是划分不行，是 naive 已最优

划分真正生效的档位与幅度（同批对照，总 cycles 577,432）：

| 线程 | naive c/s | wpt c/s | 提升 |
|--:|--:|--:|--:|
| 2 | 22.1k | 22.6k | +2.4% |
| 4 | 41.5k | 45.5k | **+9.6%（达理论界 99.6%）** |
| 8 | 71.0k | 70.8k | ≈0（地板） |
| 16 | 72.5k | 61.0k | −15%（饱和区静态箱有害） |

## 5. 8 线程之后怎么继续提升：切分抬拐点

8→16 线程 wall 纹丝不动（~8.1s），不是并行失效，而是 csa 单条 8.08s 物理封底。切开巨 trace 后，同一条缩放曲线继续爬升：

| 方案 | 12thr | 24thr | 32thr |
|---|--:|--:|--:|
| 未切分（naive/wpt） | 8.09~8.31s | 11.4s | 劣化 |
| 自适应切分 | 6.1s | 3.7s | **3.08s / 190k c/s** |

切分把拐点从 ~7 线程推到 32 线程；「切谁、切几份」的先验恰好由权重模型给出（k_i = ⌈pred_i/(Σpred/N)⌉）。

## 6. 结论：因果链与收益分解

**因果链**：稀疏注意力 → 少数单体长 trace（而非细粒度任务混合）→ 不均衡的形式是「不可分大任务」而非「分配次序差」→ 动态队列已贴地板，划分无空间 → 唯一解是切分，而权重模型提供「切谁、切几份」的先验。划分与切分是**接力关系而非替代关系**。

**收益分解（三者正交，叠乘成总账）**：

```
并行收益（1→8thr, 6.2x）    ← 线程数的功劳，naive 就有
划分收益（2/4thr, +2~10%）  ← 调度的功劳，加速贴顶
切分收益（12→32thr, +162%） ← 破坏不可分性的功劳，抬高拐点
```

11.4k（单线程）→ 45.5k（4thr wpt）→ 71k（8thr 贴地板）→ 190k（32thr 自适应切分）。

**策略落地**：低并行度（≤4thr）用权重划分加速贴顶；中高并行度先切分巨任务再派发；饱和区（带宽墙）保持动态队列、避免静态箱。稀疏度本身不改变上述任何结论——它只改变 DUT 侧 cycles，不改变宿主侧每周期成本（见 `ms = a + b·hints` 的稳定性）。
